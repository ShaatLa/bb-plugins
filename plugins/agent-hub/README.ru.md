# Agent Hub

Id плагина — `agent-hub` (раньше назывался Answers); инструменты агентов называются `agent_hub_*`; старые имена `answers_*` остаются устаревшими псевдонимами для сессий, запущенных до переименования.

Полная расшифровка открывается кнопкой Full transcript на панели разговора или в раскрытом шаге журнала. В ней показан ThreadChat выбранного треда; Back to Agent Hub возвращает ту же ленту и позицию прокрутки. Отправка из расшифровки наследует режим разрешений треда.

Кнопка оглавления рядом с поиском показывает ваши сообщения по порядку. Результаты поиска и ссылки ?msg= открывают нужное окно истории Agent Hub напрямую; прокрутка подгружает соседние окна, а Scroll to latest возвращает к текущей истории. Для якорей вне сохранённой истории доступна полная расшифровка.

Как в чате bb, сообщения, которые агент пишет подряд, без шага инструмента и рассуждения между ними, считаются одним ответом: все они остаются под журналом работы, вместе в ответе; сообщение, за которым идёт шаг инструмента, сворачивается в журнал. Раскройте шаг журнала, чтобы загрузить команду, вывод, код выхода, аргументы инструмента или diff файла. Другие данные доступны по ссылке на полную расшифровку. Текущий план агента показан одним компактным списком под разговором, когда bb отдаёт задачи.

Меню @ ищет файлы и папки в окружении выбранного треда с небольшой задержкой (до восьми путей и восьми тредов). Выбор вставляет плашку пути с метаданными упоминания bb.

[English](README.md) | Русский

Agent Hub решает простую проблему: ответы на ваши вопросы теряются среди сообщений агентов в активных тредах.

Плагин отслеживает ваши сообщения во всех тредах, кроме запущенных агентами (у них есть родительский тред), и связывает их с финальным ответом успешно завершившегося хода; небольшие вопросы агентов к вам; сообщения, которые вы сохранили вручную.

Ход, который не отвечал на ваше сообщение (завершился дочерний тред, написал другой тред или плагин), тоже попадает в разговор как **обновление**: финальное сообщение агента без вашего пузыря, с подписью об источнике («After … finished», «Message from …» с именем треда или плагина и его сообщением цитатой под ней). Подпись появляется сразу, как агент взял сообщение, и до ответа под ней виден робот; пробуждение от скрипта появляется только вместе с ответом. Если такое сообщение приходит агенту, пока он отвечает на ваше, оно встаёт над вашим сообщением, чтобы вопрос и ответ стояли рядом. Если к моменту, когда агент увидел такое сообщение посреди хода, он уже написал вам полный ответ и после этого почти ничего не делал, его последнее сообщение считается ответом на это сообщение: оно идёт под ним, после ответа вам, а вашим ответом остаётся более раннее. Идущие подряд обновления сворачиваются в одну группу «N background updates» с превью последнего (раскрывается по клику), не имеют статуса прочитанности (не попадают в счётчики) и не уходят в push; обновление, где агент, похоже, о чём-то спрашивает (`?` в конце фразы вне кода, ссылок и цитат), остаётся отдельным сообщением, считается непрочитанным и уходит в push при `notify: questions` и `all`; так же ведёт себя отчёт, который агент пометил через `agent_hub_report`. Когда тред и его подсессии затихли, самое свежее сообщение чата в группу не сворачивается: итог после серии обновлений виден целиком; пока работа идёт, свежие обновления сворачиваются, как остальные.

bb записывает `bb thread tell`, которым скрипт будит собственный тред, как сообщение пользователя. Поэтому такие сообщения должны начинаться с метки в квадратных скобках, например `[example-watcher] build finished`: Agent Hub не считает их вопросами пользователя, а ход, который они запустили, показывает как обновление с этой меткой. Ссылка `[EXA-12](…)` и `[x]` в начале сообщения меткой не считаются.

## Интерфейс

В панели навигации **Agent Hub** показывает счётчик непрочитанных ответов и открытых вопросов к вам. Доступны представления, поиск, фильтр проекта и **Mark all read**. Карточки позволяют открыть сообщение в чате, отметить прочитанным, закрепить, закрыть через **Done** или ответить. В треде есть вкладка **My questions**, а в меню сообщения — **Save to Agent Hub**.

Список **Agent Hub contacts** заменяет список тредов в боковой панели bb: те же контакты, проекты, подсессии и непрочитанные, что на странице Agent Hub. Клик по контакту открывает разговор в Agent Hub, а на уже открытой странице переключает его без перезагрузки. Повторный клик по открытому контакту отмечает его прочитанным; стрелка рядом со сводкой подсессий раскрывает и сворачивает дерево, не открывая контакт. Перетаскивание контакта или подсессии из боковой панели открывает его разговор в Agent Hub в отдельной панели; в каждой панели выбран свой разговор, а клик в списке переключает последнюю использованную панель. Кнопка **Hide contacts / Show contacts** рядом с управлением чатом полностью скрывает или возвращает левую колонку на странице Agent Hub; выбор сохраняется между открытиями. Пока список Agent Hub открыт в боковой панели, страница прячет свою колонку контактов вместе с этой кнопкой. На телефоне раскладка остаётся прежней, а при скрытой колонке разговор можно выбрать в боковой панели. Вернуть штатный список можно в **Settings → Appearance → Sidebar**; слот списка эксклюзивный.

## Инструменты агента

- `agent_hub_defer` — сообщить, что ответ будет в последующем ходе, например после делегирования. Без `id` откладывает самое новое ожидающее сообщение треда.
- `agent_hub_list` и `agent_hub_resolve` — найти отложенный вопрос и связать его с ответом текущего хода. `agent_hub_resolve` требует `id` из `agent_hub_list`; id, который не относится к ожидающему или отложенному сообщению вызывающего треда, отклоняется. Финальный ответ нужно включить в финальное сообщение этого хода.
- `agent_hub_report` — показать финальное сообщение хода в истории владельца как отчёт, а не фоновое обновление. Вызывайте в том же ходе при передаче работы владельцу (готово к проверке, ждёт его решений). Также для итога работы, когда ход начат не владельцем (другим агентом, подсессией, скриптом) и его вопросов не ждёт ни один.
- `agent_hub_ask` — задать пользователю вопрос, в том числе блокирующее решение. Ответ приходит в тред новым сообщением с цитатой вопроса. `options` принимает 1–6 разных вариантов до 200 символов, `recommended` выделяет один из них, `reason` объясняет выбор. Агент обязан задавать вопрос этим инструментом, а не писать его в чат, и затем завершить ход. Одиночному вопросу нужен `question`; `reason` требует `recommended`, а `recommended` должен совпадать с одним из `options`. Решения по конкретной задаче Work Board ведутся на её карточке.
- Составной вопрос: `agent_hub_ask` с `questions` вместо `question` (`question` тогда лишь заголовок формы и может отсутствовать; 2–10 вопросов, у каждого свои `header`, `options`, `multiSelect`, `recommended`) показывается формой bb с вкладками. Агенту уходит один ответ: по строке на каждый вопрос. `multiSelect` (и у одиночного вопроса с `options`) даёт выбрать несколько вариантов галочками; в любой форме можно дописать свой вариант.
- Повторные `agent_hub_ask` одного хода объединяются в одну форму до 10 частей: варианты и рекомендации сохраняются, срочность повышается, срок выбирается ближайший. Объединение не создаёт новый push, кроме повышения до `blocking`.
- `handoffWarnings` (по умолчанию включено) предупреждает агента при передаче работы без `agent_hub_report` или вопросе в чате без `agent_hub_ask` либо команды из проектного списка `channelCommands`. Только новые завершения верхнеуровневых тредов; архив и история при загрузке не предупреждают. Сообщение плагина с тегом `[agent-hub]` называет, что исправить, и ставится в очередь того же треда; при пропущенной передаче агент вызывает `agent_hub_report` и повторяет передачу в финальном сообщении этого хода. Ответ остаётся прочитанным и без push, пока агент не вызовет `agent_hub_report` или `agent_hub_ask`; повторного предупреждения нет. Распознавание передачи работы и **Asked in chat** сохраняются как подстраховка.
- `remindHours` в настройках уведомлений — интервал напоминаний об открытых `blocking`-вопросах (по умолчанию 3 часа, 0 отключает). Не больше трёх напоминаний; каждое приходит отдельно с возрастом вопроса и соблюдает тихие часы.
- `urgency`: `blocking` поднимает вопрос в списках и отправляет отдельный push `Blocking`; `normal` — обычный, `low` — без push. Настройки уведомлений и тихие часы действуют всегда.
- `deadlineMinutes` (целое 5–10080) задаёт срок: затем агент получает ответ по умолчанию с пометкой `Defaulted`. Необязателен; у одиночного вопроса требует `recommended`, а части без рекомендации получают `Your call`. Ответ владельца до срока имеет приоритет.
- Частичный ответ: можно ответить только на часть формы; пустые части приходят как `Skipped`, вариант `Your call` — как `Your call (decide yourself)`. Он исключает другие галочки; нужен хотя бы один ответ.
- Вопрос, который агент задал пользователю просто текстом в финальном ответе, тоже попадает в Questions — с пометкой **Asked in chat**, в счётчике и push, как вопрос из `agent_hub_ask`. Это последнее предложение со знаком «?» вне кода, ссылок, цитат и таблиц, если в нём не назван канал («на карточке», «в Agent Hub») и если за этот ход агент не вызвал ни `agent_hub_ask`, ни команду из `channelCommands`. Короткий вопрос («Хотите?») берётся вместе с предыдущим предложением. Ответ уходит в тред с цитатой вопроса; риторический вопрос закрывается кнопкой **Not a question**. Затем Agent Hub напоминает агенту вызвать `agent_hub_ask`; этот вызов заменяет пойманный вопрос на месте (вместе с вариантами), так что пользователь по-прежнему видит один вопрос.
- `agent_hub_withdraw` — отозвать свой открытый вопрос из Questions с причиной, когда ответ больше не нужен (агент нашёл его сам, передумал, спросил дважды). `id` и `reason` обязательны. Отозвать можно только неотвеченный вопрос своего треда, включая пойманный из текста чата; отвеченный, уже отозванный или чужой id отклоняется с подсказкой. Составная форма отзывается целиком. Вопрос уходит из счётчика и For me, не шлёт push и остаётся в истории с пометкой **Withdrawn** и причиной; ответить на него всё ещё можно. `agent_hub_list` показывает открытые вопросы агента с их id.

## CLI и установка

```sh
bb agent-hub list [--view unread|waiting|for_me|pinned|saved|all] [--thread ID] [--project ID] [--query TEXT] [--limit 1-50] [--cursor C] [--json]
bb agent-hub get ID [--json]
bb agent-hub read <ids...> | --all [--thread ID]
bb agent-hub status [--thread ID]
bb agent-hub digest [--since 24h|7d|ISO-дата] [--json]
bb plugin install git:https://github.com/ShaatLa/bb-plugins.git@0.x --plugin agent-hub --tag-prefix agent-hub/
```

## Ограничения

- Сообщения плагинов (CI Dashboard, Slots и т. п.) и всё, что приходит в треды, запущенные агентами, вопросами не считается: там «пользовательские» сообщения пишут агенты и скрипты. Вопросы агентов из таких тредов через `agent_hub_ask` попадают в «For me».

- Несколько вопросов в одном ходе получают общий ответ этого хода.
- Если агент забыл вызвать `agent_hub_defer`, сообщение вроде «делегировал, доложу позже» считается ответом: чип **Looks like an interim reply** предлагает **Keep waiting** или **It's the answer**.
- Уже работающие треды получат инструменты после запуска следующей сессии провайдера.
- Первичная загрузка истории охватывает активные за последние 48 часов треды, до примерно 1500 последних подходящих событий на тред и не более 1000 тредов.
- Ответ с неопределённой доставкой автоматически не отправляется повторно.
- Неудавшиеся ходы разрешения вопроса нельзя повторить через **Retry**.
- Push-события первой загрузки истории после запуска пропускаются.

## Inbox, цитаты и пулы ответов (0.2)

По умолчанию открывается **Inbox**: слева треды с непрочитанными ответами и вопросами к вам, справа история выбранного треда от старых сообщений к новым. Тред, из которого вы ушли, прокрутив вверх, открывается там же (новое ниже по-прежнему отмечено разделителем **New**, и есть **Scroll to latest**). Иначе тред открывается на первом непрочитанном сообщении под разделителем **New**, а если всё прочитано — на самом новом. Как в Telegram, сообщение отмечается прочитанным без таймера, как только его конец показался на экране или уехал выше: короткое — сразу, длинное — когда долистаешь до конца. Повторный клик по выбранному треду отмечает прочитанным весь тред. Выбранный тред остаётся в списке. **Load earlier** подгружает историю, сохраняя позицию чтения. На узком экране **Back** возвращает к списку. Старые представления **Waiting**, **For me**, **Pinned**, **Saved**, **All** сохраняют поиск и фильтр проекта.

Во вкладке треда **My questions** виды выбираются в меню слева вверху: **Unread** — новые ответы в этом треде, **Awaiting answer** — ваши вопросы без ответа, **Saved** — сохранённые и отмеченные звёздочкой ответы, **History** — всё подряд с поиском. **Mark all read** доступна в Inbox и Unread.

Действия на карточке показываются только там, где они что-то меняют: **Mark read** — у непрочитанного; **Stop waiting** — у вашего вопроса без ответа (убирает его из Awaiting answer); **Won’t reply** — тихая кнопка рядом с вариантами ответа у вопроса агента (приглушает его: уходит из Inbox, счётчиков, пушей и напоминаний; вопрос остаётся открытым, виден в Questions и агенту, ему ничего не отправляется); **Remove from Saved** — у сохранённого сообщения. Всё убранное остаётся в History.

Короткое сообщение без «?» (до 60 символов), на которое агент ответил коротко (до 160 символов), сразу считается прочитанным и во «Входящие» не попадает. Сообщения с «?» помечены «Question».

На странице Agent Hub переключатель **Chats | Questions | Saved** вверху (у Questions — число ждущих вопросов; Saved — сообщения, сохранённые через Save, с поиском и фильтром по проекту) выбирает между разговорами и отдельным разделом вопросов: одна стопка всех ждущих вопросов из всех тредов, от старых к новым, — и блокирующие формы bb (вопросы и одобрения, включая дочерние треды), и неблокирующие вопросы агентов к вам. В каждой карточке — тред, проект, возраст и ссылка **Open thread**; после ответа карточка исчезает. Ответить можно и прямо в открытом чате: над композером треда в bb и в беседе Chats карточка **Questions for you** показывает открытые вопросы агента этого треда (в Chats рядом — и блокирующие формы bb), композер при этом не прячется, а ответ в любом месте закрывает вопрос везде; открытые вопросы агента появляются в истории только после ответа, но входят в число у контакта (явные вопросы подсессий учитываются в Questions и на значке, не создавая контакт) и остаются в нём до ответа, даже после «прочитано»; тред с ждущим вопросом помечен значком на аватаре. Горячие клавиши формы (цифры, действия) работают только в форме с фокусом.

У контакта с подсессиями вместо превью — их сводка (прямые и вложенные, сколько работают и сколько стоят). Стрелка в конце сводки раскрывает и сворачивает дерево; выбор сохраняется между открытиями. Строки сохраняют направляющие вложенности, иконку провайдера и значок работы из сайдбара bb. Клик по подсессии открывает её чат в Agent Hub и закрывает боковую панель на телефоне; перетаскивание открывает этот чат Agent Hub в отдельной панели, а при недоступности разделения навигации — тред bb. Подсвечивается выбранный чат Agent Hub или активный тред bb. История подсессии загружается при первом открытии; новые события обрабатывает тот же драйвер с ограничением объёма, что и у контактов. Сообщения подсессий остаются прочитанными и исключены из контактов, Inbox, счётчиков, общей истории, Saved, поиска, Questions, Owed и push; текст чата не создаёт вопрос «Asked in chat». Явный вызов `agent_hub_ask` по-прежнему создаёт вопрос владельцу, включая уведомления и блокирующие напоминания; результат `agent_hub_report` остаётся в прочитанной истории подсессии. Заголовок, композер и вкладки Info, Diff и Work Board следуют за выбранной подсессией. В меню bb по правому клику есть **Copy ID**.

Выделите текст ответа, промежуточного сообщения или вопроса агента: появится компактная панель без смены фокуса, выделение можно скопировать. **Add to chat** добавляет Markdown-цитату к черновику текущего треда; **Add to reply pool** сохраняет отрывок без заметки; **Comment** открывает форму ответа; **Save** сохраняет отрывок в Agent Hub, если доступен номер сообщения. Панель появляется под выделением (над ним, только если снизу нет места); на сенсорном экране — с небольшой задержкой. Escape или снятие выделения закрывает панель.

Поле ввода всегда занимает две строки: редактор на всю ширину и панель снизу с вложениями, а в основном чате — выбором модели, уровня рассуждений и тарифа bb. Между голосовым вводом и отправкой оставлено не менее 12px. Начальное значение берётся из последнего запуска или настроек провайдера; выбор сохраняется отдельно для каждого треда вместе с черновиком и используется при отправке, steer, планировании и сохранении черновика.

В поле ввода строки, начинающиеся с `> `, показываются цитатой. Shift+Enter в цитате продолжает её, а на пустой строке цитаты выходит из неё к обычному тексту. **Quote** в меню правой кнопки над выделенным текстом или ⌘⇧9 (Ctrl+Shift+9) превращает выделенные строки (или строку с курсором) в цитату, повторно — снимает её. Это меню Agent Hub (Undo, Redo, Quote, Cut, Copy, Paste, Delete, Select All): пункт в меню bb плагин добавить не может. Без выделения открывается обычное меню bb с подсказками орфографии. Отмена у поля своя (⌘Z, ⇧⌘Z и Edit → Undo/Redo): она охватывает и вставку, и цитаты, и ссылки на треды; набор текста без паузы в секунду отменяется одним шагом.

В **Reply pools** показаны все пулы по тредам. Заметки сохраняются при уходе из поля и через 800 мс без ввода. **Send all** сначала ждёт сохранения всех заметок и отправляет цитаты одним сообщением; ошибка сохранения отменяет отправку. При конфликте версии локальный текст остаётся для повторного применения. Изменённые во время отправки записи сохраняются; интерфейс показывает их количество. При неопределённой доставке проверьте чат перед повторной отправкой.

Пока в пуле треда есть хотя бы одна запись, форма цитаты продолжает собирать в него: Enter и основная кнопка добавляют в пул, а прямая отправка переезжает в меню кнопки как **Send now**. После отправки пула всё возвращается как было.

В меню сообщения чата **Add to reply pool** добавляет выделенный текст или всё сообщение и открывает **My questions**, где пул треда расположен над вопросами. Цитата ограничена 20 000 символами, заметка — 8 000, сообщение пула — 32 000; превышение не обрезается молча. Форматирование таблиц и формул при преобразовании HTML в Markdown может отличаться от исходного.

## Новое в 0.3

**Inbox** показывает все разговоры, включая прочитанные. После массового чтения доступен **Undo** в течение 8 секунд. **Save to Agent Hub** показывает подтверждение и ссылку на **Saved**. Своё отправленное сообщение можно исправить кнопкой **Edit message**, как в bb: тред откатывается к этому сообщению и запускается заново с новым текстом, а всё, что было после, пропадает и из чата Agent Hub. Сообщение, ход которого вы остановили, остаётся в чате без ответа, но уходит из Inbox.

В разговоре есть поиск по вопросам и ответам с переходом к найденному сообщению. Вопросы одного хода с общим ответом объединяются в карточку. Снизу можно написать сообщение, приложить файлы, запланировать отправку, сохранить черновик или направить сообщение в активный ход. Вопросы `agent_hub_ask` с `options` показывают кнопки быстрого ответа. Ссылки агента на локальные файлы открываются в панели просмотра файлов bb справа, как в чате треда: файлы окружения треда — как файлы рабочей копии, остальные — как файлы хоста; `#L12` и `:12` открывают нужную строку. В поле ввода «/» (или «$») открывает список команд и скилов провайдера треда, как в чате bb; выбранный вставляется плашкой, текст сообщения остаётся `/имя`.

Если установлен плагин **Tokenomos**, в строке под полем ввода видны иконка Tokenomos и стоимость сессии в долларах по ценам API (только своя); `~` значит оценку или неполные данные. Клик открывает стоимость за сегодня и 7 дней, модели и саб-сессии. Без Tokenomos шапка не меняется.

Чат рисует каждое сообщение по автору, в одном из трёх видов: пузырь **владельца** (время, Copy, Copy link, Save to Agent Hub, Edit), текст **агента** и **входящее** сообщение, которое в тред положил кто-то другой (другой тред, плагин, уведомление bb вроде завершившегося или упавшего дочернего треда, `[метка]` скрипта). У входящего одна шапка (значок, отправитель, глагол, время) и его текст цитатой в три строки; в его ряду только раскрытие и Copy link, а ответ агента стоит под ним как обычное сообщение агента. Любой обрезанный текст раскрывается той же иконкой-шевроном слева в ряду своего сообщения. На сенсорных экранах ряды всегда видны, зона нажатия 32px.

У текста агента один ряд: Copy, Copy link и меню **More**. Меню **More** содержит **Save** / **Remove from Saved**, **Remind later** и, при доступном Work Board, **Create task** с выбором проекта. Напоминание скрывает запись до выбранного времени; **Unsnooze** возвращает её. Неудавшийся ход помечается **Turn failed** с кнопкой **Retry**.

Настройка `notify`: `off` — выкл., `asked` — вопросы агента к вам, `questions` — также ответы на ваши сообщения с вопросительным знаком, `all` — все подходящие события. По умолчанию `asked`: bb уже уведомляет о завершённых ходах, поэтому ответы отдельно не отправляются. `quietHours` задаёт местный интервал `HH:MM-HH:MM`; события за него сводятся в одно уведомление после окончания интервала. Для доставки нужен плагин Push Notifications.

`bb agent-hub digest` выводит новые ответы за последние 24 часа, ожидающие вопросы и вопросы агента к вам. `--since 7d` или ISO-дата меняют период новых ответов, `--json` даёт JSON. Например, в плагине Automations можно создать ежедневное задание агента с командой `bb agent-hub digest --since 24h`.

`bb agent-hub list` возвращает одну страницу, по умолчанию 20 записей (`--limit` до 50); в текстовом выводе каждая запись сокращена до строки, а при наличии следующей страницы в конце стоит `More: --cursor C`. `bb agent-hub get ID` выводит одну запись целиком. `bb agent-hub status` показывает счётчики, число активных и архивных тредов под наблюдением и 10 последних ошибок приёма; `--thread ID` — один тред.

В боковой панели Agent Hub есть вкладки Info, Diff и Work Board, которые привязаны к открытому чату. Info отображает окружение, ветку, коммиты и изменённые файлы. Diff сравнивает незафиксированные изменения или правки в ветках, а отметки о просмотре сохраняются через Git-плагин bb. Work Board показывает собственную доску Work Board для проекта, привязанного к чату (фильтры, перетаскивание, карточки задач); её рисует сам Work Board, а задачи этого чата обведены. Вкладки доступны только для чтения, пока они видны, и обновляются после завершения хода в чате; для недоступных интеграций отображается пустое состояние или ошибка.

Карточка Owed позволяет перейти к старым отложенным ответам, подтвердить их или отклонить; такие ответы истекают через три дня, если с них не начат новый ход.

Сообщения владельца остаются обычным текстом: ссылки, задачи Work Board, упоминания тредов и известные команды или скилы после `/` и `$` показываются плашками, как в поле ввода. Это работает и в цитатах, эхо ответа, очереди и списке ожидаемых ответов. Превью Background updates занимает две строки и сохраняет плашки тредов; ответы агента и сообщения плагинов используют Markdown bb.

Сообщения агента и владельца предлагают Copy (Markdown) и Copy link рядом с действиями сообщения, с краткой обратной связью. Ссылки ведут в чат bb к номеру сообщения, если он доступен.

Для грубого указателя область нажатия кнопок — минимум 40×40px, без изменения значков и настольной раскладки. Вопросы и подтверждения сворачиваются вместе; состояние хранится в памяти для каждого чата. На сенсорном устройстве блок выше 40% экрана изначально свёрнут. Вложения сохраняются через механизм bb.

Заголовок выбранного чата показывает название средствами bb, ссылку на родительский чат внутри Agent Hub и меню действий bb. Переименование использует диалог bb; подтверждения жизненного цикла и сброс выбора остаются штатными.

Copy link — отдельная иконка в ряду каждого сообщения; промежуточные ответы используют ту же иконку.

На компьютере аватар и заголовок открытого чата, разделы, поиск в строке, Mark all read и меню треда находятся на одной панели. На телефоне Back, заголовок, поиск в строке и меню треда остаются в шапке чата.

При сбое показывается причина из события завершения провайдера, если она доступна; Retry остаётся. Прерванный ход отмечается спокойно и больше не считается ожидаемым ответом или Owed, включая отложенные вопросы.

Режим разрешений рядом с моделью берётся из настроек выполнения треда. Выбор хранится в черновике каждого треда и применяется при отправке, вмешательстве, сохранении и отправке по расписанию; неизвестный режим не передаётся. Правка очереди сохраняет разрешения её запроса.

В активной панели Agent Hub доступны переназначаемые команды Focus composer (Mod+Alt+L), Search conversation (Mod+Alt+F) и Thread actions (Mod+Alt+T). В других панелях они не действуют. Up в начале пустого поля вызывает историю сообщений треда; Up/Down перебирают её, Down после самого нового восстанавливает черновик и вложения.

Смена провайдера включает Handoff to new thread; Exit handoff возвращает провайдера исходного треда. Отправка создаёт и выбирает новый тред в том же проекте и окружении с выбранной моделью и провайдером. Сообщение начинается с `Continue from @thread:<source-id>` (упоминание с названием треда), затем пустая строка и ваш текст. Исходный тред не меняется.

## Уведомления от других плагинов

Плагин, который не может доставить отчёт в поток менеджера, передаёт его Agent Hub через RPC `notice` (`bb.sdk.plugins.callRpc({ pluginId: 'agent-hub', method: 'notice', input })`).

| Вход | |
|---|---|
| `source` | id плагина-отправителя, 1–200 символов. |
| `tickId` | Стабильный ключ исходного отчёта, 1–500 символов. |
| `projectId` | id проекта bb, 1–200 символов. |
| `threadId` | Необязательно, предполагаемый поток менеджера, до 200 символов. |
| `title` | 1–200 символов после обрезки пробелов. |
| `markdown` | Отчёт, от 1 байта до 1 МиБ в UTF-8. |

Результат — `{ id, created }`. Повтор с тем же `(source, tickId)` вернёт тот же `id` с `created: false` и сохранит первый текст. Возвращённый `id` значит, что уведомление сохранено. Неизвестные поля входа игнорируются. Ошибка валидации (пустое или слишком длинное поле, текст больше 1 МиБ) — окончательный отказ: отчёт не сохранён, и повтор с теми же данными закончится так же. Любая другая ошибка может означать, что уведомление сохранено, поэтому повторяйте с тем же `tickId`.

Уведомление — непрочитанное обновление, которое требует внимания, как `agent_hub_report`: оно входит в счётчик Inbox и бейдж, приходит пушем на всех уровнях уведомлений, кроме `off`, включая `asked`: починить менеджера, не принявшего отчёт, можете только вы, в тихие часы откладывается. Если `threadId` годится, оно показывается в чате этого потока. Если поток в архиве, удалён, является подсессией или неизвестен либо `threadId` не указан, уведомление хранится без потока и показывается в разделе **Questions** под своим проектом, со ссылкой на предполагаемого менеджера, если он есть; поток, который позже архивируют или удалят, так же передаёт туда свои уведомления. Пока уведомление не обработано, оно перечислено и в **Questions**. Длинный отчёт сначала показан превью: **Show full report** подгружает остальное. **Mark read** — «обработано». Открытие потока менеджера в bb не помечает уведомление прочитанным. Отчёты хранятся до обработки и автоматически не удаляются.

## Настройки

Откройте **Settings → Plugins → Agent Hub**. Notifications управляет push-уведомлениями, тихими часами (местное время From/To) и напоминаниями. Chat выбирает Agent Hub или bb chat. Contacts включает группировку по проектам и сброс порядка проектов. Agents управляет предупреждениями об обходе инструментов Agent Hub. Изменения применяются сразу на всех клиентах. Семь настроек хранятся в KV плагина в `preferences`; старые значения переносятся один раз без перезаписи последующих изменений. При миграции старый блок Configuration может остаться до следующей перезагрузки плагина.

В Chat также доступны **Show "Mark all read"** (по умолчанию выключено), **Working animation** (Desktop only: на сенсорных экранах неподвижный робот), **Enter on touch screens** (New line; можно выбрать Send, Shift+Enter всегда переносит строку), **Group background updates** (включено) и **Actions on selected text** (включено). Отключение действий не мешает выделению и копированию; меню сообщений остаются доступны. При отключённой анимации и reduced motion робот неподвижен, циклы анимации не работают. Пять параметров хранятся в том же KV и применяются сразу.

Распознавание каналов задаётся для проекта: `channelCommands` по умолчанию равно `["work-board question add"]`. Команда, содержащая любой фрагмент списка, считается вопросом через канал; `agent_hub_ask` учитывается всегда. Для тредов без проекта используется значение по умолчанию. Это распознавание не задаёт агентам правил выбора канала.

```sh
bb agent-hub config get [<key>] [--project <id>] [--json]
bb agent-hub config set <key> <value> [--project <id>] [--json]
```

Без `--project` команды читают и меняют глобальные preferences; с ним — настройки проекта (сейчас только `channelCommands`, без поля на странице настроек). Без ключа `get` возвращает все значения выбранной области, с ключом — только его значение; `set` возвращает сохранённое значение.
RPC: `config.get {projectId?, key?}`, `config.set {projectId?, key, value}`. Existing whole-object preference RPCs remain available. Global changes use the settings page’s validation and live-change path. Unknown keys list valid keys. Booleans and numbers accept JSON literals; selects and quiet hours accept strings. `channelCommands` accepts a JSON array of non-empty strings (including `[]` to disable extra channels) or a comma-separated list.

The CLI command is `bb agent-hub`.

First start reads the old `plugins/answers/data.db` with SQLite online backup before ingestion starts, including all cursors. KV (`preferences`, `config:project:*`) and legacy settings are read from the host's `bb.db` in read-only mode; legacy settings become preferences. Secret files, if present, are copied with mode 0600. Old data stays in place for rollback. A completion record in the new database prevents another migration. Failures roll back copied KV and secrets and retry on the next start; a populated new database is never overwritten.

`bb agent-hub migration status --json` returns `{ran, completedAt, kvKeys, secrets, error, oldItemCount, newItemCount, matchingItemIds}`. Counts are current; matching IDs sample up to twenty new rows. `completedAt` is an ISO timestamp or null; a missing old database has a null count.

The question card header toggles the pending stack, keeping the header and count visible. Collapse is remembered per thread; tall stacks start collapsed on phones.

Choose **Add to reply pool** from the main composer’s send menu to move its text and attachments into this thread’s pool and open the Pools tab. The action appears when the composer has content.

Drop files or images from the OS onto a reply pool header or its empty area to create an entry, or onto an existing entry to add attachments. Uploads use the thread’s project and the same ten-attachment limit as the composer. Attachment chips do not provide a custom drag-out format.

If import fails, the empty database stays read-only and automatic ingestion pauses until restart, keeping retries safe. Preferences and migration status remain available. An already populated new database is preserved and reported as a migration conflict.

Когда окно bb с Agent Hub открыто и уведомления разрешены, Agent Hub показывает уведомления сам; нажатие открывает его беседу (или страницу Agent Hub для сводки). Блокировка выбирает одну вкладку браузера. Без активного клиента используется Push Notifications; на телефоне нажатие открывает чат bb. Открытие чата из любого уведомления (bb, Work Board, телефон) продолжается в Agent Hub. Разрешением управляет Push Notifications.

Последние пять открытых бесед остаются смонтированными. Скрытые чаты приостанавливают подписки и эффекты; возврат сразу сохраняет прокрутку, раскрытые карточки, транскрипт и состояние редактора, затем обновляет данные на месте. Шестая беседа вытесняет самую давно открытую; после вытеснения или перезагрузки страницы используется сохранённая позиция прокрутки.
