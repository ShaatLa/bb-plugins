---
name: sweep
description: Inspect Sweep status, resolve the project manager, or run repository checks manually.
---
Read scheduled status with `bb sweep status --project proj_example --json` and statistics with `bb sweep stats --days 7 --project proj_example`. `bb sweep manager --project proj_example` returns the configured thread ID or null. Plugins use Sweep RPC `manager` with `{"projectId":"proj_example"}` and check thread availability before sending.

Set the Git URL in the bb project settings. Use `bb sweep config get manager --project proj_example` to read one field and `bb sweep config set manager thr_example --project proj_example` to change it. Check status before redirecting reports. A new manager receives pending reports too. Pass exactly one explicit `--project` on every `config set` and `run` call. `bb sweep config --help` lists the keys, formats and ranges. Set `branch` and the repository-relative `script` before enabling, for example `main` and `checks/sweep.py`. Pass arrays as JSON, for example `bb sweep config set args '["--brief"]' --project proj_example`. Use `bb plugin config sweep set bbCli /opt/bin/bb` for the global executable override. It must be an absolute path. Use `unset bbCli` to inherit the server environment.

`bb sweep run --project proj_example --dry-run` refreshes the checkout and executes the configured script. Sweep does not update scheduled status, deliver reports or acknowledge snapshots. `--dry-run` is optional and applies only to `run`. The script must avoid external writes when used for a read-only check. Read the README protocol before enabling `snapshots`. For example, write a complete JSON candidate with `{"seen":[]}` to the candidate path and leave the committed path untouched. Keep the previous automation enabled until the project manager confirms a successful scheduled Sweep check in `status`.

When Sweep reports worktrees under an archived thread, the manager must verify the thread is still archived, each path is still registered in the project's repository and each removal candidate is clean. Use `git worktree list --porcelain` from that repository and `git -C '/path/to/thread-storage/thr_example/worktree' status --porcelain`. List dirty worktrees separately and leave them alone. Ask the owner in Agent Hub to approve removal of the exact clean paths. After approval, recheck the same paths and remove only those still eligible with `git worktree remove -- '/path/to/thread-storage/thr_example/worktree'` from the verified repository. Never use `--force` or delete the directories directly. Sweep itself only reports them.

Runner handoff (0.7.0): Work Board decides which plugin runs a project's checks. Install Work Board 0.71.0 first, then Sweep 0.7.0; Sweep claims each project once and keeps running. A project marked in `bb sweep status` (`handoff.sent`) was moved to Work Board and refuses runs and enabling until `bb work-board checks export-to-sweep --project ABC` brings it back. Use the `bb work-board checks import-from-sweep|export-to-sweep|cancel-sweep-send|abort-send|release` commands, for the owner or on the owner's instruction; do not call the `transfer.*` RPCs by hand.
